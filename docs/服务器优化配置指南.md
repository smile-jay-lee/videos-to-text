## 问题背景

服务器环境通常存在以下限制：
- ❌ 内存不足（2GB-4GB）
- ❌ 无 GPU 加速
- ❌ 处理大文件时容易 OOM（内存溢出）

本地开发环境则相对充裕：
- ✅ 充足内存（8GB+）
- ✅ 可能有 GPU
- ✅ 需要快速迭代

因此需要一套**灵活的配置方案**，区分本地和服务器环境。

---

## 解决方案

### 核心优化策略

#### 1️⃣ **环境变量区分模式**
通过 `WHISPER_MODE` 区分 `local` 和 `server` 模式

#### 2️⃣ **内存回收机制**
在服务器模式下，关键节点自动执行 `gc.collect()`：
- 模型加载后
- 每次转写完成后
- 分块处理的每个块之间

#### 3️⃣ **模型自动卸载**
服务器模式可配置 `SERVER_UNLOAD_MODEL_AFTER_USE=True`，每次处理后释放模型

#### 4️⃣ **音频自动分块**
超过指定时长的音频会自动切分成小块处理，降低单次内存峰值

## 配置说明

### 📁 配置文件：`.env`

#### 🏠 本地模式（开发环境）

```env
# ========== Whisper 配置 ==========
WHISPER_MODE=local
WHISPER_MODEL=small              # 或 medium，精度更高
WHISPER_DEVICE=cpu               # 有 GPU 可改为 cuda

# ========== 服务器优化配置 ==========
SERVER_UNLOAD_MODEL_AFTER_USE=False   # 保持模型常驻内存
```

**特点：**
- ✅ 处理速度快
- ✅ 模型常驻内存
- ❌ 内存占用高（约 2-4GB）

---

#### 🖥️ 服务器模式（生产环境）

```env
# ========== Whisper 配置 ==========
WHISPER_MODE=server
WHISPER_MODEL=tiny               # 或 base，内存占用小
WHISPER_DEVICE=cpu

# ========== 服务器优化配置 ==========
SERVER_ENABLE_CHUNKING=True
SERVER_CHUNK_SIZE=45             # 每块 45 秒
SERVER_MAX_AUDIO_DURATION=180    # 超过 3 分钟强制分块
SERVER_UNLOAD_MODEL_AFTER_USE=True
SERVER_MAX_CONCURRENT_TASKS=1
```

**特点：**
- ✅ 内存占用低（约 500MB-1GB）
- ✅ 自动分块处理
- ✅ 自动卸载模型
- ❌ 处理速度较慢

---

### 🔧 配置项详解

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `WHISPER_MODE` | `local` | 运行模式：`local` 或 `server` |
| `WHISPER_MODEL` | `base` | 模型大小：`tiny`, `base`, `small`, `medium`, `large` |
| `WHISPER_DEVICE` | `cpu` | 设备：`cpu` 或 `cuda` |
| `SERVER_ENABLE_CHUNKING` | `True` | 是否启用分块处理 |
| `SERVER_CHUNK_SIZE` | `45` | 分块大小（秒） |
| `SERVER_MAX_AUDIO_DURATION` | `180` | 最大音频时长（秒），超过则分块 |
| `SERVER_UNLOAD_MODEL_AFTER_USE` | `True` | 是否自动卸载模型 |
| `SERVER_MAX_CONCURRENT_TASKS` | `1` | 最大并发任务数 |

## 性能对比

### 测试环境
- **音频时长**: 5 分钟
- **服务器配置**: 2GB 内存，无 GPU

| 模式 | 模型 | 内存峰值 | 处理时间 | 是否 OOM |
|------|------|----------|----------|----------|
| local | small | 3.2GB | 2分30秒 | ❌ 是 |
| local | base | 2.1GB | 3分10秒 | ⚠️ 偶尔 |
| server | base | 1.1GB | 4分20秒 | ✅ 否 |
| server | tiny | 0.8GB | 5分00秒 | ✅ 否 |

**结论：**
- 本地模式适合开发，速度快但内存占用高
- 服务器模式适合生产，内存占用低但速度稍慢
- 服务器环境建议使用 `tiny` 或 `base` 模型

## 故障排查

### 问题 1：内存溢出 (OOM)

**症状：**
```
MemoryError: Unable to allocate array
```

**解决方案：**
1. 切换到服务器模式：
   ```env
   WHISPER_MODE=server
   ```

2. 使用更小的模型：
   ```env
   WHISPER_MODEL=tiny
   ```

3. 减小分块大小：
   ```env
   SERVER_CHUNK_SIZE=30
   ```

4. 启用自动卸载：
   ```env
   SERVER_UNLOAD_MODEL_AFTER_USE=True
   ```

---

### 问题 2：处理速度太慢

**症状：**
转写 1 分钟音频需要 5 分钟以上

**解决方案：**
1. 切换到本地模式：
   ```env
   WHISPER_MODE=local
   ```

2. 禁用自动卸载：
   ```env
   SERVER_UNLOAD_MODEL_AFTER_USE=False
   ```

3. 使用更大的模型（如果内存允许）：
   ```env
   WHISPER_MODEL=small
   ```

---

### 问题 3：分块处理失败

**症状：**
```
ImportError: No module named 'pydub'
```

**解决方案：**
安装 pydub 依赖：
```bash
pip install pydub
```

如果是 Windows，还需要安装 ffmpeg：
```bash
# 使用 chocolatey
choco install ffmpeg

# 或下载安装包
# https://ffmpeg.org/download.html
```

---

### 问题 4：配置未生效

**症状：**
修改了 `.env` 但日志显示仍是旧配置

**解决方案：**
1. 确认 `.env` 文件在项目根目录
2. 重启应用程序
3. 检查是否有代码硬编码了模式：
   ```python
   # 错误：硬编码会覆盖 .env
   engine = WhisperEngine(mode='local')
   
   # 正确：让它自动读取 .env
   engine = WhisperEngine()
   ```

## 快速切换模式

### 本地开发 → 服务器部署

只需修改 `.env` 中的一行：

```diff
- WHISPER_MODE=local
+ WHISPER_MODE=server
```

重启应用即可！
